# Phase 3 — the VGM player (the original Sega soundtrack from the player's own files)

Branch `phase3/vgm` from `phase3/integration` `dc2061e`. Spec §6 *Original files*, §12 (IP); research
`p3map/music.md` §2 (the plan), `p3map/research.md` §9 (the 22 tracks). Contract C8: the music stream loads
`VgmDeck` into its mixer (worklet and worker) and reads files with `src/formats/vgm.js`.

Nothing of the original is in the repo. The player brings their own rip of the Mega Drive soundtrack (a
`.vgm`, a `.vgz` or a zip of them); this code replays its register log through our own chips. Every test
builds its VGM bytes inside the test. The measurements below were made in scratch with a rip pack that
never left scratch.

## VgmDeck

- **Shape (C8).** `new VgmDeck(id, bytes, { sampleRate, passes = 0, gain = 1 })` with `id, delay, gain, pass,
  ending, pos, endedAt, done`, `fade(to, seconds)`, `render(L, R, at, n)` (adds into L/R), `finish()`; also
  `error` (a broken log stops the deck, render never throws), `seconds`, `debug()`.
- **Time.** The chips run at the YM2612's own rate (clock / 144: 53,267 Hz on an NTSC console), the PSG's
  steps averaged into the same frames (its clock is master/15, the YM2612's master/7, so the ratio comes from
  the header). A command logged at VGM sample s takes effect before chip frame round(s x rate / 44,100),
  in exact integers, so the time base never drifts however long a track plays. A file with no YM2612 runs
  at the rate a YM2612 would have beside its PSG.
- **Resampler.** A 32-tap Kaiser-windowed sinc (beta 7, cutoff 0.46 of the output rate), 64 phases
  interpolated linearly, one multiply-add per tap; tables are shared by every deck at one rate. Passed
  straight through when the rates match.
- **The log.** Data blocks (type 0x00: the YM2612's PCM bank) are found by a scan that runs ahead of the
  player 8,192 commands at a time, so a large file costs nothing up front and a loop never appends a block
  twice. 0xE0 seeks; 0x8n writes the bank byte to the DAC and then waits n (not n + 1); DAC streams 0x90-0x95
  (set-up, data, frequency, start by offset/length/ms/to-the-end, start by block, stop, reverse and loop
  flags) write at their own frequency on the exact frame. Other chips' commands are skipped with their
  operands; an undefined command or a cut-short file ends the log (as the spec says).
- **Loops.** `passes` counts loop bodies (0: for ever); the header's loop modifier and base scale the
  passes asked for. A file with no loop point starts again from the top when it plays for ever. A pass
  that advances no time ends the track instead of spinning the audio thread.
- **The end.** `finish()` keys every FM channel off, turns the DAC off, silences the PSG and stops streams;
  the track rings out until the chip is silent or 4 s, and the last second of those 4 s is a fade (a note
  with release rate 0, like the Opening's last chord, would otherwise stop with a click). A fade the mixer
  already started is left alone.
- **Level.** Chip full scale is 1.0 (the six YM2612 channels at full output sum to 32,768); the header's
  volume modifier and `gain` multiply it. The YM2612's resting DAC ladder step (6 x 4 of 390 -> 504 of
  32,768) is taken off, and the resampler's history starts on it, so a track starts and ends on silence and
  the mixer's 40 Hz high-pass never sees a step. The PSG joins at `PSG_LEVEL` against the YM2612 (below).
- **warmUp(sampleRate).** Plays a made-up moment of sound (an FM note, a DAC ramp from a data block, a PSG
  tone) through the player once, so its code is compiled and its filter built before the first real track.
  In a fresh AudioWorkletGlobalScope the first deck otherwise took 12-52 ms to build and its first blocks up
  to 37 ms, all on the audio thread.
- **Where it runs.** Static imports only (`../../formats/vgm.js`, `./chips/*`), no DOM, no TextDecoder, no
  DecompressionStream: checked inside a real AudioWorkletGlobalScope in Chrome (below). Inflating and zips
  happen on the main thread at import; the deck takes plain VGM bytes.

## Decisions

- **ymfm, ported.** Research §2.4: ymfm is BSD-3 and integer-exact, Nuked-OPN2 is LGPL and about 8x the CPU,
  Genesis Plus GX is non-commercial, MAME's old cores GPL. The port keeps ymfm's integer maths and is
  proven sample for sample against the C++ (below). Two savings that change no output: fully released
  operators are not clocked, and a register write that changes nothing does not re-prepare the channel
  (except in CSM mode, where re-preparing would end the timer's key-on).
- **The YM2612's 9-bit DAC is kept.** ymfm (like Nuked and the hardware) truncates each channel to 9 bits;
  libvgm's default core keeps 14. On the quietest tracks (the dirges, about -35 LUFS at native scale) that
  grain is what is left above 8 kHz: about -37 dB of the total per third-octave against libvgm's -48 to
  -54 dB. Running the same tracks as a YM3438 (no ladder step) changes nothing there, so it is the
  truncation, not the ladder.
- **Native scale; loudness is the mixer's.** The deck plays at chip scale; the tracks measure -29.9 to -39.2
  LUFS that way (table below). The music stream's mixer passes `gain: VGM_GAIN` (5, +14 dB, one gain for every
  track so the original's balance between its tracks stays) to sit beside the FM tracks at -18 LUFS. The
  deck's own level must not be raised as well.
- **PSG balance.** `PSG_LEVEL` 0.34: a full-volume PSG tone swings a quarter of a full-level FM carrier
  (4,200 against 16,384), the balance Genesis Plus GX's author tuned to a VA4 Model 1 (`PSG_MAX_VOLUME`
  2,800 at its default 150 % PSG preamp, FM at 100 %). Checked on the six rips that use the PSG, each chip
  rendered alone: libvgm's defaults (VGMPlay's chip table, PSG 0x80 against YM2612 0x100) sit 1.1 dB above
  it. libvgm doubles a chip's volume when it plays alone, so its solo renders were corrected (verified: its
  full render is exactly FM-only + 0.5 x PSG-only, residual -89.5 dB). The first value, 0.5, was 3.3 dB
  louder than the Model 1. Consoles differ by model and revision; this follows the one measured.
- **The tail fades** over its last second (above).

## Proof

- **Bit-exact YM2612.** 19 register scripts made up in `tests/fixtures/vgm/ym2612-scripts.mjs` (every
  algorithm; feedback 0-7; detune x multiple; envelopes with key scaling and every rate; SSG-EG modes;
  LFO AM and PM at every depth; CH3 special mode; CSM with timers; the DAC and pan; the frequency latch;
  key-on per operator; raw bus writes; two seeded fuzz runs; a driver's redundant timer acks; a long
  mixed piece; and the YM3438 for algorithms, DAC and fuzz) ran through the C++ ymfm (commit 81aec25) in a
  scratch harness. `ym2612-golden.json` keeps the CRC32 of each 8,192-sample chunk of its Int16 stereo
  output (about 590,000 stereo samples in all); the port matches every chunk. No C++ at test time.
- **Bit-exact on real logs (scratch).** Five tracks of the rip (Opening: 214,000 DAC writes, channel 3
  special mode and timer acks; Ammon's Advice, Radnor's Scheme and the Ordos Dirge: LFO rewritten all the
  time; Conquest) were turned into the same kind of script, with the deck's frame rounding, and run through
  the C++ ymfm: the deck's own chip frames (direct rate, PSG muted, no level or offset) are identical for
  all 10.8 million frames.
- **PSG.** Goertzel pitch (period 254 -> 440 Hz), 2 dB steps and 15 = off, power-up state, period 0 and
  the 0x400 flag, the 18.6 kHz average, periodic noise period at each rate, noise rate 3 following tone 2,
  the shift register reload on a noise write, the Sega register's 57,337-step white noise cycle, silence
  and Game Gear stereo.
- **Deck.** A register write lands on the exact sample its wait ends on; 0x8n byte by byte with 0xE0;
  data blocks read once and joined in order, found far into the log before the player gets there; passes
  and the exact end sample; for ever; loop modifier and base; no loop point; the zero-length loop guard;
  ring-out (fast release done early, slow release capped at 4 s, the tail fade, finish() from outside);
  gain and the volume modifier; a fade to 0 ends the deck; the PSG at its level and pitch in the same
  frames; DAC streams by offset and length, by block, looped, reversed and stopped; resampled to 48 kHz
  (pitch, timing, no NaN); a silent chip is silence from the first sample at any rate; warmUp; the real
  `MusicMixer` starting a queued track on the very sample a VgmDeck ends; bad input.
- **Format.** Header versions, the volume modifier, header bytes past the data offset, YM3438 and other
  or second chips reported, GD3 in UTF-16LE beyond Latin script, the command scan, unsupported features
  listed, reserved command lengths before and after 1.60, damaged headers, random bytes after a header
  (never hangs, only ever a VgmError), a .vgz round trip through node:zlib, a gzip bomb stopped at 32 MB,
  zips with stored and deflated .vgm/.vgz entries, and refusals.

- **Timing and pitch.** Every track matches libvgm in pitch (0 cents), in length (the VGM header's samples
  exactly; ours is longer only by its ring-out) and in loop point (checked on the looped tracks with two
  passes against two-loop renders). Lag 0-2 samples is the resamplers.
- **The level difference** (-7 to -8.5 dB) is scale only: libvgm doubles its output for this chip pair
  (overall-volume normalisation) and its YM2612 core's full scale differs. Tracks 4 and 10 differ less
  because libvgm's MAME/GPGX core renders them quieter than Nuked-OPN2 does (below).
- **The large band differences** of tracks 4, 12, 16 and 17 are above 6 kHz on quiet tracks: the
  YM2612's 9-bit grain (Decisions); running them as a YM3438 leaves them unchanged, and Nuked has them too.

- **Against Nuked-OPN2** (libvgm's `FCC_NUKE` core, a die-shot emulation; a scratch build of `vgm2wav`),

  samples) the waveforms correlate 0.84-0.99 (Atreides Dirge 0.99), except the tracks whose LFO register is
  rewritten all the time (3, 4, 10, 12, 17: 0.0-0.56).
- **The PSG change** (0.5 -> 0.34) raised the waveform correlation on every PSG track: 01 0.89 -> 0.92,
  05 0.92 -> 0.93, 06 0.87 -> 0.90, 07 0.88 -> 0.90, 08 0.89 -> 0.91, 09 0.41 -> 0.56.
- **The reference mp3s** of the pack (another player, mostly two loops and a fade) give the same picture:
  pitch 0 cents, band differences within 2.5 dB except the same quiet tracks, -6.4 to -8.2 dB level
  except tracks 4 (-3.1) and 10 (-5.3) again.

  streams). Profile (Finale): YM2612 operators and envelopes 65 %, resampler 18 %, PSG 6 %, log 3 %. Run

  5.9-7.0 %: about 1.8 times as much.
- **In Chrome** (headless, a real AudioWorkletGlobalScope at 48 kHz, the deck alone, timed with the
  worklet's own clock over 1,500-block windows, load average about 28): 7.7-13 % of the audio thread,
  worst block 1-16 ms (preemption at that load), no errors, no TextDecoder or DecompressionStream needed.
  `warmUp` took 57-176 ms there, on the audio thread, under that load (12-52 ms for the first deck without
  it when the machine was quiet); the deck then builds in 1-2 ms.
- **Ring-out.** Release tails end in 0.15-2.75 s; three tracks (Opening, Turbulence, Spice Trip) still hold a
  note with release rate 0 at the cap, which now fades over the last second.

## How to test

- `node --test tests/vgm-*.test.mjs` (about 1 s).
- `node scripts/vgm-info.mjs <your pack.zip>` lists what is inside a rip and what the player would leave out.
- To hear a file outside the game (Node, scratch): `new VgmDeck('x', bytes, { sampleRate: 44100, passes: 1 })`,
  render 1,024 samples at a time until `done`, write the floats as a WAV. In the game the music stream's
  Original files page loads the files.
- Re-making the golden file needs the C++ ymfm (not in the repo). `scriptText()` in
  `tests/fixtures/vgm/ym2612-scripts.mjs` writes the scripts as text (`s <name> <ym2612|ym3438>`, `w <part>
  <reg> <data>`, `p <offset> <data>`, `n <samples>`); a 60-line harness reads it, runs each script on a
  reset `ymfm::ym2612` or `ymfm::ym3438` (a `w` is `write(2 * part, reg)` then `write(2 * part + 1, data)`;
  each `n` sample ticks timers A and B in whole samples, as the port does, then calls `generate()`), clamps
  to Int16 and writes raw stereo; `chunkCrcs()` in `tests/fixtures/vgm/helpers.mjs` turns that into the
  golden file's CRCs.

## Open questions

- **LFO-heavy tracks** (3 Ammon's Advice, 4 Radnor's Scheme, 10 Starport, 12 Chosen Destiny, 17 Ordos
  Dirge) match Nuked-OPN2 in level and (except a band of Ammon's Advice) in spectrum, but their waveforms
  drift apart; each rewrites the LFO register every quarter second or so, and every voice has vibrato, so
  the LFO is the likely difference. The port matches C++ ymfm exactly on three of these logs (above), so
  the difference lies upstream between ymfm and Nuked (libvgm's MAME/GPGX core differs from both). Nobody
  has judged by ear yet whether it is audible.
- **The 9-bit grain** on the quietest tracks is the chip's (above). If the manager hears it as hiss, a
  14-bit option is a small change in `ym2612.js` (the >> 5 truncation in `channel()`, its 9-bit clamp and
  the output scale); not done, as the hardware is 9-bit.
- **The PSG balance** follows a VA4 Model 1. A Model 2 console is said to differ; nothing here measured one.
- **CPU.** About 1.8x the FM synth's cost per track (above); while the mixer crossfades two VGM tracks both
  run. The resampler is 18 % of the deck's time; at 48 kHz a 16-tap filter would do (no alias can land below
  21 kHz there), if the audio thread ever needs it.
- **PAL rips** play at their own clock (pitch and tempo from the header); the pack measured is NTSC.

## Review fixes

Three minor findings from the report-only review, each reproduced as a failing test first
(`tests/vgm-format.test.mjs`, `tests/vgm-deck.test.mjs`, "review fix" / the last three format tests).

- **Zip cap.** `readVgmZip`'s 256 MB total counted the sizes the directory declares, so a 33 KB zip listing
  one deflated 32 MB file twelve times as 0 bytes unpacked 384 MB. Now each entry must unpack to exactly its
  declared size: a deflated entry is inflated with that size as its cap (stopped one chunk past it), a stored
  entry's two sizes must agree before it is copied. The declared total then bounds what is really unpacked.
- **Absurd clocks and stream rates.** A clock no chip runs at (YM2612 outside 1-16 MHz, PSG outside
  0.5-8 MHz) is now a `VgmError` from `readHeader`, so `parseVgm` and the deck both refuse it with the
  reason. Not listed under `unsupported` as the reviewer suggested: the music stream's import only notes
  `unsupported` and still keeps the file, and a refusal is what such a file needs. A DAC stream faster than
  the chip (0x92 up to 2^31 Hz) no longer writes every byte due: only the last byte due in a frame is
  written (the only one the DAC would sound), so it keeps its time (as VGMPlay's DAC control does, rather
  than clamping the rate, which would slow it down) at one write a frame. The reviewer's case went from
  253 ms to 0.07 ms per 128-sample block; normal streams (one byte a frame or slower) are unchanged.
- **EOF offset 0.** A header whose EOF field is 0, or points before the music data, is read to the file's
  end with a warning, as VGMPlay does, instead of being refused.

Checked again: the reviewer's scripts and failing tests now pass; the 22-track rip still parses and opens
with no warnings (scratch only).

## For the README

**Original Sega soundtrack.** If you have your own rip of the Mega Drive soundtrack of *Dune: The Battle for
Arrakis* as VGM files (`.vgm`, `.vgz`, or a `.zip` of them), the game can play it instead of its own music:
the files are replayed through an emulated YM2612 and PSG in the browser, never uploaded and never part of
this repository. `node scripts/vgm-info.mjs <files or zip>` shows what is inside a rip.

Credits: the YM2612 emulation (`src/audio/music/chips/ym2612.js`) is a JavaScript port of
[ymfm](https://github.com/aaronsgiles/ymfm) by Aaron Giles, BSD-3-Clause; its licence is kept in the file
header. The PSG is our own code.
